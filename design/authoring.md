# 서사 제작 — 구조 발굴과 시점 분할

> **카드를 쓰기 전에 무엇을 하는가.** 세계관 토대 = `world/` · 회귀의 의미 = `3_return.md` ·
> 게임 작동 = `core_loop.md` · 카드 의미 = `specs/cards.md`. 이 문서 = 서사를 만드는 방법.
> ※ 이 문서가 정하지 않는 것 = "## 경계".

## 원전을 다루는 태도

```yaml
원전은 정답지가 아니라 퇴적층이다.
Chronicle에서는 플롯을 창작하기 전에 구조를 발굴한다.

신화·전설·역사는 그대로 재현할 정답지가 아니라 구조와 모티프를 채굴하는 재료다.
실제 인물·사건의 이름만 바꿔 옮기는 방식은 Chronicle의 기본 제작법이 아니다.
```

## 제작 흐름

```text
원전 구조 발굴
  → 고유명사 제거 / 기능 추출
  → 보존 · 분할 · 병합 · 반전 · 삭제 · 추가
  → Chronicle 고유 사건 재구축
  → 객관적 사건 지도 · 타임라인
  → 제한 시점 분할
  → Situation / Decision / 결과 작성
```

## 구조 추출

```yaml
먼저 고유명사를 걷어내고, 인물·사건이 수행하는 기능·관계·구조를 추출한다.
추출한 구조는 필요에 따라 다루어 Chronicle 고유 사건으로 재구축한다.
  보존 — 그 구조를 뼈대로 유지한다.
  분할 — 원전 한 인물의 역할을 여러 인물로 나눈다.
  병합 — 원전 여러 인물의 기능을 한 사람에게 합친다.
  반전 — 인물의 역할·관계·위치·의미를 뒤집는다.
  삭제 — Chronicle에 필요 없는 것을 덜어낸다.
  추가 — Chronicle 고유의 것을 넣는다.
```

## 객관적 사건 지도

```yaml
개별 카드를 쓰기 전에, 작가가 보는 객관적 사건 지도·타임라인을 먼저 만든다.
  이것은 작가 전용이다. 플레이어는 그 전체를 직접 보지 않는다.
그 객관적 사건을 인물별 제한된 시점으로 분해한다.
```

## 제한 시점과 교차

```yaml
제한 시점으로 분해한 사건 사실을 Situation 작성의 입력으로 삼는다.
  # Situation의 의미·역할 = specs/cards.md §상황 카드 (정본).

서로 다른 관점의 이야기들이 각자 부분을 보여주고,
  함께 접했을 때 더 큰 사건이 드러나는 구조를 지향한다.
```
