## 1. 용어 체계

### 유저 대면 (게임 내 표시)

| 계층 | 형식 | 예시 |
|------|------|------|
| 인물 | 이름 | 테오도라 |
| 권 (= Order) | N권 [제목] | 1권 [다리 위의 서자들] |
| 장 (= Chapter) | N장 [제목] | 1장 [도하 저지] ← 운명 카드가 제목을 줌 |
| 막 (= Stage) | N장 N막 | 1장 1막, 1장 2막 |

- **시리즈 개념 폐기.** 유저에게 비노출. 전체 몇 편이 있는지 모르게 한다.
- **팩 개념 폐기.** 권 = 풀. 카드는 개별적으로 풀에 존재.

### 시스템 내부 (위키/개발용)

| 계층 | ID 형식 | 예시 |
|------|---------|------|
| 인물 | `{인물}` | `THEODORA` |
| 권 | `{인물}-V{N}` | `THEODORA-V1` |
| 전투 카드 | `{권}-C{NNN}` | `THEODORA-V1-C001` ~ `C200` |
| 사건 카드 | `{권}-E{NNN}` | `THEODORA-V1-E001` ~ `E200` |
| 우연 카드 | `{권}-CH{NNN}` | `THEODORA-V1-CH001` ~ `CH050` |
| 운명 카드 | `{권}-F{NN}` | `THEODORA-V1-F01` ~ `F24` |

## 2. 핵심 구조: 권 = 풀

```
테오도라 1권 [다리 위의 서자들]
 ├─ 전투 풀  (~200장)
 ├─ 사건 풀  (~200장)
 ├─ 우연 풀  (~50장)
 ├─ 운명 풀  (~24장)
 ├─ 배경 풀  (장소 / 상황 / 계절)
 ├─ 적 테이블 (권-장위치-막위치 레벨 공용)
 └─ 권 규칙  (페이즈 수, 뽑기 수, 셔플 제약)
```

### 3층 독립 구조

| 층 | 역할 | 변경 시 다른 층 영향 |
|----|------|-------------------|
| 풀 층 | 카드 공급. 스토아 팩토리가 여기에 투입 | 없음 |
| 규칙 층 | 뽑기 규칙, 페이즈, 셔플 제약, 적 테이블. 권 단위 설정 | 없음 |
| 전투 층 | 7스텝 엔진. 카드가 조건 세팅, 엔진이 결과 산출 | 없음 |

## 3. 런 동선

```
1. 런 시작
2. 슬롯머신 연출 — 동시 결정:
   a. 장 3개 구성: 운명 풀에서 6장 비중복 뽑기 (막당 1장)
      → 운명 카드가 장 제목을 결정
   b. 각 장에 배경 배정: [장소] / [상황] / [계절] 독립 롤
      → 상황이 우연 주입 수를 결정
   c. 화면에 인물 / 운명 / 배경 제시

3. 장 진행:
   1장 = 2페이즈 (도입)
   2장 = 3페이즈 (전개)
   3장 = 3페이즈 (절정)

4. 각 막 시작 시:
   a. 전투 풀에서 3장 뽑기 (런 내 비중복)
   b. 사건 풀에서 3장 뽑기 (런 내 비중복)
   c. 우연 풀에서 N장 뽑기 (상황이 결정. 런 내 비중복)
   d. 운명 카드 1장 (런 시작 시 이미 배정됨)
   e. 전투+사건+우연 셔플 → 페이즈 진행

5. 페이즈:
   a. 셔플된 카드에서 뒷면 3장 제시
   b. 유저 블라인드 2장 선택
   c. 안 뽑힌 1장 → 전해지지 않은 이야기 (뒷면 채 퇴장)
   d. 선택한 2장 뒤집기 → 순서 결정 → 순차 플레이

6. 모든 페이즈 종료 후 → 운명 카드 → 운명 전투

7. 장 전환 시:
   업적 카드 (존폐 보류) + 부상 전원 회복
```

## 4. 페이즈 구조

### 블라인드 선택

| 항목 | 내용 |
|------|------|
| 카드 제시 | 뒷면 3장. 전투/사건/우연 구분 불가 (뒷면 동일) |
| 선택 | 유저가 2장 블라인드 선택 |
| 버림 | 안 뽑힌 1장 = "전해지지 않은 이야기". 뒷면 채 퇴장. 내용 미공개 |
| 뒤집기 | 선택한 2장 공개 |
| 순서 | 유저가 2장의 플레이 순서 결정 → 순차 플레이 |
| 핵심 경험 | "닥친 상황에 적응". 블라인드 = 정보 부족, 순서 결정 = 적응, 플레이 = 판단 |

### 셔플 제약

| 규칙 | 내용 |
|------|------|
| 같은 유형 3장 불가 | 한 페이즈에 전투-전투-전투, 사건-사건-사건 불가 |
| 우연 페이즈당 최대 1장 | 한 페이즈에 우연 2장 이상 불가 |

### 페이즈 수 (권 규칙)

| 장 위치 | 페이즈 수 | 성격 |
|---------|----------|------|
| 1장 | 2페이즈 | 도입. 짧고 가벼움 |
| 2장 | 3페이즈 | 전개. 본격적 |
| 3장 | 3페이즈 | 절정. 운명 전투 앞의 마지막 준비 |

> 페이즈 수는 권 규칙으로 설정 가능. 다른 권이나 인물에서는 다를 수 있음.

### 막 1개 카드 구성

| 항목 | 2페이즈 막 | 3페이즈 막 |
|------|-----------|-----------|
| 전투 | 3장 | 3장 |
| 사건 | 3장 | 3장 |
| 우연 | 상황 의존 (0~3장) | 상황 의존 (3~5장) |
| 운명 | 1장 | 1장 |
| 셔플 대상 | 6+우연 | 6+우연 |
| 공개 | 6장 | 9장 |
| 체험 | 4장 | 6장 |
| 전해지지 않은 이야기 | 2장 | 3장 |
| 미공개 | 셔플-공개 차이분 | 셔플-공개 차이분 |

## 5. 우연 카드

### 권 공용 풀

| 항목 | 내용 |
|------|------|
| 소속 | 권 전체 공용 풀 |
| 주입 수 | 배경의 **상황**이 결정 |
| 소모 | 런 내 비중복 |
| 핵심 | 유저가 피할 수 없는 "통제 밖의 사건". 인생에 우연이란 정말 많이 일어남 |

### 상황별 우연 주입

| 상황 | 우연 보장 수 | 성격 |
|------|------------|------|
| 평시 | 낮음 (0~1) | 안정된 런 |
| 강행군 | 중간 (1~2) | 불안정한 런 |
| 역병 | 높음 (2~3) | 혼란스러운 런 |
| 퇴각 | 높음 (2~3) | 급박한 런 |

> 상황 풀 상세는 배경 시스템 설계 시 확정. 위 표는 방향만.

### 현재 우연 라벨 (3종, 확장 필수)

| 라벨 | 효과 |
|------|------|
| [복잡한 운명] | 아군 랜덤 1기 [단조] |
| [탈영] | Nameless 랜덤 1기 제거 |
| [복병] | 강제 전투. 적만 선제 |

> 풀 50장을 3종 라벨로 채우면 라벨당 16장. 우연 라벨 확장이 이 구조의 전제 조건.

## 6. 운명 카드

### 장의 정체성 = 운명 카드

| 항목 | 내용 |
|------|------|
| 풀 | 권당 ~24장 |
| 뽑기 | 런 시작 시 6장 비중복 뽑기 (막당 1장) |
| 역할 | 장 제목 + 운명 조건 + 최종 전투 |
| 위치 | 각 막 마지막. 페이즈 전부 종료 후 자동 |
| 품질 | 수작업 수준으로 개별 설계. 게임 품질의 천장 |
| 구성 | 전략 라벨 1개(필수) + 전술/결과 라벨 + 운명 조건 + 적 테이블 |

```
런 시작 → 운명 6장 배정:
 1장 1막: F07 [도하 저지]
 1장 2막: F15 [야영지 습격]
 2장 1막: F03 [석벽의 포위]
 2장 2막: F21 [혈전]
 3장 1막: F11 [최후의 다리]
 3장 2막: F19 [서자의 증명]

유저에게 보이는 것:
 "1장 [도하 저지]" ← 1막 운명 카드 제목
 운명 조건: 화면 상시 표시
```

## 7. 배경 시스템

### 3축 독립 롤

| 축 | 단위 | 역할 |
|----|------|------|
| 장소 | 장 단위 | 전투 조건 (협로/평원/성채/강변/산지) |
| 상황 | 장 단위 | **우연 주입 수 결정** + 특수 규칙 |
| 계절 | 장 단위 | 환경 조건 (가을 유리 / 겨울 불리 / 봄·여름 미정) |

> 상황이 우연 빈도를 조절. "역병이 도는 시기"는 우연이 많고 불안정, "평시"는 적고 안정.
> 배경 상세는 배경.md 참조. 장소/상황 메카닉은 미확정 (방향만).

## 8. 난이도 스케일링

### 적 테이블은 권-장-막 레벨 공용

| 항목 | 내용 |
|------|------|
| 원칙 | 후반 장이 전반 장보다 어려움 |
| 방법 | 적 테이블을 **권-장위치-막위치 레벨**에서 관리 |
| 구조 | "1권 1장 1막의 전투에서 나오는 적은 이 테이블에서 선택된다" |
| 대상 | 전투 카드 + 운명 카드 |
| 비전투 | 사건/우연은 난이도 스케일링 없음 |

### 적 테이블 물량

| 단위 | 수 |
|------|-----|
| 장 위치 | 3개 (1장/2장/3장) |
| 막 위치 | 2개 (1막/2막) |
| **1권 적 테이블** | **6세트** |

## 9. 1권 전체 물량

| 항목 | 합계 |
|------|------|
| 전투 풀 | ~200장 |
| 사건 풀 | ~200장 |
| 우연 풀 | ~50장 |
| 운명 풀 | ~24장 |
| **1권 총합** | **~474장** |

> 풀 크기는 목표치. 스토아 팩토리 양산 + 수작업 운명으로 채움.
> 전투/사건은 라벨-태그 조합 × 서술 변형. 같은 라벨 조합에 서술만 다른 카드 다수 허용.

### 런당 소모량 (3페이즈 기준 최대)

| 항목 | 산출 | 합계 |
|------|------|------|
| 전투 | 6막 × 3장 | 18장 |
| 사건 | 6막 × 3장 | 18장 |
| 우연 | 상황 의존 | 6~18장 |
| 운명 | 6막 × 1장 | 6장 |
| **런당 총합** | | **48~60장** |

> 런 내 비중복. 풀 대비 소모율 약 10~13%.

## 10. 전해지지 않은 이야기

| 항목 | 내용 |
|------|------|
| 정의 | 페이즈에서 유저가 선택하지 않은 카드 + 미공개 카드 |
| 공개 | 없음. 뒷면 채 퇴장. 내용 미공개 |
| 연출 | 모든 버림 카드 동일 연출 |
| 수량 | 막당 페이즈 수만큼 (2페이즈=2장, 3페이즈=3장) + 미공개 |
| 서사 | 정사(쓰여진 것) / 야사(비공식) / 미기록(쓰여지지 않은 것) / **전해지지 않은 이야기(있었지만 전해지지 않은 것)** |

## 11. 서술 작성 원칙

### 카드 자기 완결 원칙

| 규칙 | 내용 |
|------|------|
| 카드 독립 | 모든 카드는 다른 카드의 존재/결과를 전제하지 않음 |
| 권 설정만 참조 | 테오도라 정체, 서자 부대, 권의 대전제만 참조 가능 |
| 배경 독립 | 카드 서술은 특정 장소/계절에 의존하지 않음 |
| 추상도 | 어떤 운명/배경 조합에서도 어울릴 수 있는 수준으로 작성 |

> 풀에서 뽑히는 구조이므로 어떤 카드와 조합되어도 작동해야 함.
> 스토아 팩토리 프롬프트 제약 조건으로 반영 필요.

## 13. 확장 모델

| 항목 | 내용 |
|------|------|
| DLC 단위 | **새 인물 또는 새 권.** 권 = 풀 전체 |
| 권별 라벨/태그 | 1권은 이 라벨들, 2권은 새 라벨 추가. 하스스톤 확장팩 키워드 모델 |
| 확장 방법 | 풀에 카드 추가. 끝. 뽑기 규칙 변경 없음 |
| 유저 인지 | "2권에서는 [새 라벨]이 나온다" |
| 장 수 확장 | 권에 따라 3장/4장/5장 가능 (권 규칙 조정) |

## 14. 설계 근거

| 질문 | 답변 |
|------|------|
| 왜 풀 구조인가? | 팩이 묶어주는 게 실질적으로 없었음. 카드 자기 완결 + 적 테이블 공용 + 배경 독립이면 팩 불필요. 풀이 극단적으로 단순하고 확장 비용이 0 |
| 왜 팩을 폐기했는가? | 팩의 역할(서사 묶음)이 카드 자기 완결 원칙과 충돌. 팩 간 카드 공유/비중복 규칙이 복잡성만 추가 |
| 왜 블라인드 선택인가? | "정보는 부족하고 현장은 이미 달라져 있다" — 핵심 경험 목표의 구조적 구현 |
| 왜 뒷면이 동일한가? | 카테고리로 가치 판단하는 것을 막기 위해. 전투=나쁨, 사건=좋음이 되면 판단이 아님 |
| 왜 운명이 장 제목인가? | 풀에서 유일하게 장에 정체성을 줄 수 있는 요소. 운명 = 이 장의 목표이자 이름 |
| 왜 상황이 우연 수를 결정하나? | 페이즈 수와 우연 빈도를 분리. 배경의 깡통 문제 해결. 상황이 실질적 메카닉을 가짐 |
| 왜 유저가 다 담을 수 없는가? | Chronicle의 설계 철학. 모르는 것, 대처할 수 없는 것, 우연과의 끝없는 조우 |
| 왜 474장인가? | 스토아 팩토리가 양산. 라벨-태그 조합 × 서술 변형. 같은 메카닉에 서술만 다른 카드 허용 |

## 15. 폐기 사항
