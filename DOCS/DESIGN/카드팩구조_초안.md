# 카드팩 구조 설계 초안

> **작성일:** 2026-03-07 · **상태:** 초안 (기획 세션 산출물) · **문서화 세션에서 위키 반영 필요**

---

## 1. 용어 체계

### 유저 대면 (게임 내 표시)

| 계층 | 형식 | 예시 |
|------|------|------|
| 인물 | 이름 | 테오도라 |
| 권 (= Order) | N권 [제목] | 1권 [다리 위의 서자들] |
| 장 (= Chapter) | N장 [제목] | 1장 [빗속의 결투] |
| 막 (= Stage) | N장 N막 | 1장 1막, 1장 2막 |

- **시리즈 개념 폐기.** 유저에게 비노출. 전체 몇 편이 있는지 모르게 한다.
- "쓰여지지 않은 이야기는 목차에도 없다"는 기존 원칙과 일치.

### 시스템 내부 (위키/개발용)

| 계층 | ID 형식 | 예시 |
|------|---------|------|
| 인물 | `{인물}` | `THEODORA` |
| 권 | `{인물}-V{N}` | `THEODORA-V1` |
| 팩 | `{인물}-V{N}-P{NN}` | `THEODORA-V1-P01` ~ `P12` |
| 블록 | `{인물}-V{N}-P{NN}-{A/B}` | `THEODORA-V1-P01-A` |
| 전투 카드 | `{팩블록}-C{N}` | `THEODORA-V1-P01-A-C1`, `C2` |
| 사건 카드 | `{팩블록}-E{N}` | `THEODORA-V1-P01-A-E1`, `E2` |
| 운명 카드 | `{팩블록}-F` | `THEODORA-V1-P01-A-F` |
| 우연 카드 | `{인물}-V{N}-CH{NN}` | `THEODORA-V1-CH01` ~ `CH12` |

> 우연 카드는 팩/블록에 소속되지 않음. 권 공용 풀 소속.

## 2. 전체 파이프라인

```
권(캠페인)
 ├─ 스토리 팩 × 12
 │   ├─ 블록 A (1막용) — 5장 고정 + 우연 1장(런타임 주입)
 │   └─ 블록 B (2막용) — 5장 고정 + 우연 1장(런타임 주입)
 │
 └─ 우연 풀 — 권 공용. N장. 막마다 1장 랜덤 주입
```

### 런 시작 → 플레이 동선

```
1. 런 시작
2. 슬롯머신 연출 — 동시 결정:
   a. 12팩 중 3팩 비중복 선택 → 장 3개 구성
   b. 각 장에 배경(장소 × 계절 × 상황) 배정 — 장마다 독립 롤
   c. 화면에 [인물] / [배경] / [계절] 슬롯머신 식으로 제시
3. 각 장 = 팩 1개 = 블록 A(1막) → 블록 B(2막)
   - 장 위치(1장/2장/3장)에 따라 적 테이블 스케일링
4. 각 막 시작 시:
   a. 블록 고정 5장 + 우연 풀에서 1장 주입 = 6장
   b. 이야기 카드 5장 셔플 (운명 제외)
   c. 운명 카드 고정 마지막 (6번째)
5. 카드 순차 뒤집기 → 분기 선택 → 효과 적용
6. 6번째 운명 카드 → 운명 전투
```

## 3. 팩 구조 (빌딩 블록)

### 팩 1개 = 블록 2개 = 10장 (우연 제외)

```
팩 P01
├─ 블록 A (1막용, 5장)
│   ├─ P01-A-C1  전투 카드
│   ├─ P01-A-C2  전투 카드
│   ├─ P01-A-E1  사건 카드
│   ├─ P01-A-E2  사건 카드
│   └─ P01-A-F   운명 카드 (고정 6번째)
│
└─ 블록 B (2막용, 5장)
    ├─ P01-B-C1  전투 카드
    ├─ P01-B-C2  전투 카드
    ├─ P01-B-E1  사건 카드
    ├─ P01-B-E2  사건 카드
    └─ P01-B-F   운명 카드 (고정 6번째)
```

### 블록 구성 규칙

| 카드 유형 | 장수 | 셔플 | 위치 |
|-----------|------|------|------|
| 전투 카드 | 2 | 셔플 대상 | 랜덤 |
| 사건 카드 | 2 | 셔플 대상 | 랜덤 |
| 우연 카드 | 1 | 셔플 대상 | 랜덤 (권 공용 풀에서 주입) |
| 운명 카드 | 1 | 셔플 제외 | 고정 마지막 (6번째) |

### 블록 순서: A = 1막, B = 2막. 고정.

- A가 항상 먼저, B가 항상 나중.
- B는 A의 **톤 에스컬레이션** 가능 (예: "상황이 악화되었다" 수준의 분위기 참조).
- B는 A의 **구체적 분기 결과** 참조 불가 (유저 선택 모름).
- A는 B를 참조 불가.
- 강한 서사 연결 불필요. 막 단위로 이야기가 성립하면 충분.

---

## 4. 셔플 규칙

### 같은 유형 연속 불가

이야기 카드 5장(전투 2 + 사건 2 + 우연 1) 셔플 시, 같은 유형 카드가 연속 배치되면 리셔플.

- 전투-전투 ✕
- 사건-사건 ✕
- 우연은 1장이라 연속 자체 불가

## 5. 우연 카드 풀

### 권 공용 풀

| 항목 | 내용 |
|------|------|
| 소속 | 팩/블록 귀속 아님. 권 전체 공용 |
| 풀 크기 | 권당 N장 (18~24장 권장. 후반 막 예측 가능성 완화. 라벨 확장 시 조정) |
| 주입 | 막 시작 시 풀에서 1장 랜덤 뽑기 → 블록에 삽입 |
| 소모 | 1런 = 6막 = 6장 소모. 같은 런 내 중복 불가 |
| 근거 | 우연의 본질 = "통제 밖의 사건". 팩에 귀속되면 리플레이 시 예측 가능해져 우연의 의미 소실 |

### 현재 우연 라벨 (3종, 확장 예정)

| 라벨 | 효과 |
|------|------|
| [복잡한 운명] | 아군 랜덤 1기 [단조] |
| [탈영] | Nameless 랜덤 1기 제거 |
| [복병] | 강제 전투. 적만 선제 |

## 6. 운명 카드

### 블록 귀속 확정

| 항목 | 내용 |
|------|------|
| 소속 | 블록에 귀속. 팩 설계 시 개별 작성 |
| 위치 | 항상 마지막 (6번째). 셔플 제외 |
| 구성 | 전략 라벨 1개(필수) + 전술/결과 라벨 + 운명 조건 + 적 테이블 |
| 물량 | 1권 = 팩 12 × 블록 2 = 24장 |
| 기존 변경 | "운명 카드 풀 시리즈 간 공유" → 폐기. 블록 귀속으로 변경 |

## 7. 난이도 스케일링

### 적 테이블은 권-장-막 레벨 공용

| 항목 | 내용 |
|------|------|
| 원칙 | 같은 팩이 1장에 오면 쉽고 3장에 오면 어려움 |
| 방법 | 적 테이블을 카드 개별이 아닌 **권-장위치-막위치 레벨**에서 관리 |
| 구조 | "1권 1장 1막의 전투 카드에서 나오는 적은 아래 테이블에서 선택된다" |
| 대상 | 전투 카드 + 운명 카드 (적 테이블 보유 카드만) |
| 비전투 | 사건/우연 카드는 난이도 스케일링 없음. 위치 무관 동일 |

### 적 테이블 물량

| 단위 | 수 |
|------|-----|
| 장 위치 | 3개 (1장/2장/3장) |
| 막 위치 | 2개 (1막/2막) |
| **1권 적 테이블** | **6세트** |

> 전투 카드는 자기 블록 소속 서술 + 라벨을 가지되, 적 구성은 카드가 깔리는 장-막 위치의 테이블에서 결정. 운명 카드도 동일.

## 9. 분기 원천

| 원천 | 계산 | 비고 |
|------|------|------|
| 팩 선택 | 12 × 11 × 10 = 1,320 | 순서 있는 순열 (장 위치별 난이도 다름) |
| 우연 카드 조합 | C(N,6) | 풀 크기 의존. N=18이면 C(18,6) = 18,564 |
| 셔플 순서 | 막당 수십 가지 | 유형 연속 불가 제약 |
| 배경 (장소 × 계절 × 상황) | 장마다 독립 롤 | 배경 풀 크기 의존 |

> **체감 다양성에 대한 정직한 평가:** 숫자상 조합은 폭발적이지만, 같은 팩이 다른 장 위치에 오면 적 테이블만 바뀌고 카드 서술은 동일하다. 유저가 "이 장은 저번에도 봤네"라고 느끼는 건 피할 수 없다. 리플레이 가치의 핵심은 조합 수가 아니라, 다른 팩 조합에서 오는 전략 변화와 배경/우연의 랜덤성에 있다.

## 10. 서술 작성 원칙

### 카드 자기 완결 원칙

| 규칙 | 내용 |
|------|------|
| 카드 간 참조 금지 | 같은 블록 내 다른 카드의 분기 결과를 전제하지 않음 (셔플 때문) |
| 블록 간 참조 | B는 A의 톤/전제 상황 참조 가능, 구체적 분기 결과 참조 불가 |
| 권 설정 참조 | 테오도라 정체, 서자 부대, 권의 대전제만 참조 가능 |
| 배경 독립 | 카드 서술은 특정 장소/계절에 의존하지 않음 (배경은 메카닉 조건만) |

→ 스토아 팩토리 프롬프트 제약 조건으로 반영 필요.

## 12. 확장 모델

| 항목 | 내용 |
|------|------|
| DLC 단위 | **새 인물 또는 새 권.** 기존 권에 팩 추가가 아님. 인물 = 테오도라 같은 플레이어블 캐릭터 |
| 장 수 확장 | 권에 따라 3장/4장/5장 가능 (팩 수와 뽑는 수 조절) |
| 팩 수 | 기본 12개(3×4). 권에 따라 10개, 15개 등 조절 가능. 핵심은 "뽑는 수보다 충분히 많은 풀" |
| 블록 비율 변형 | 기본 = 전투2+사건2+운명1. 확장 시 "격전 블록"(전투3+사건1+운명1) 등 허용 여지 |
| 셔플 변형 | 기본 = 같은 유형 연속 불가. 특수 팩에서 완화 가능 여지 |
| 우연 라벨 확장 | 기본 3종 → 추후 추가 |

### 팩 12개의 설계 근거

| 근거 | 설명 |
|------|------|
| 3×4 구조 | 런당 3장 뽑기에 대해 풀이 4배. 매 런 전체의 25%만 경험 |
| 리플레이 곡선 | 4런 정도면 대부분의 팩을 1회 이상 경험하되, 모든 조합은 경험 못 함 |
| 유연성 | 팩 수 자체는 10~15 범위에서 조절 가능. 12는 출발점 |

## 13. 설계 근거

| 질문 | 답변 |
|------|------|
| 왜 팩 구조인가? | 스토아 팩토리 생산 단위와 일치. 팩 하나를 설계하면 장 하나가 완성. 확장 시 팩을 추가하면 끝 |
| 왜 블록 A→B 고정인가? | 순서 랜덤의 이점(×2 분기)보다, 톤 에스컬레이션이 가능해지는 설계 자유도가 더 큼. 리플레이 가치는 이미 충분 |
| 왜 우연이 권 공용인가? | 같은 팩을 다시 만나도 우연만은 매번 다르게. 우연의 서사적 본질(통제 밖) 보존 |
| 왜 운명이 블록 귀속인가? | 운명은 "이 에피소드의 최종 전투". 팩의 서사와 묶여야 자연스러움 |
| 왜 적 테이블이 권-장-막 공용인가? | 카드별 테이블이면 물량 폭발(216세트). 공용이면 6세트. 1인 개발 현실 |
| 왜 전투:사건 2:2인가? | 초안 리듬. 운명 포함 50% 전투. 프로토타입 후 조정 가능 |
| 왜 배경과 팩 동시 결정인가? | 유저에게 "이번 런의 조건"을 한 번에 제시. 슬롯머신 연출로 몰입 |
| 왜 시리즈를 폐기했는가? | 12팩 임의 조합이 시리즈 묶음보다 조합 폭이 넓고, 유저에게 전체 편수를 숨길 수 있음 |

---

## 14. 폐기 사항

| 항목 | 사유 |
|------|------|
| 시리즈 묶음 | 불필요. 팩 임의 조합으로 대체 |
| 범용/전용 비율 (70/30) | 팩 비중복 선택으로 구조적 자동 해결 |
| 운명 카드 풀 시리즈 간 공유 | 운명은 블록 귀속으로 변경 |
| 우연 카드 블록 귀속 | 우연은 권 공용 풀로 변경 |

## 15. 미확정 사항

| 우연 풀 크기 | 18~24장 권장. 후반 막 예측 완화 목적 | 우연 라벨 확장 |
