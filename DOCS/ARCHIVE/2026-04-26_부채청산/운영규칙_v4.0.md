# ⚙️ 운영 규칙 v4.0

> Chronicle 위키 작성·관리 규칙. **AI 독자 기준** (Claude / Claude Code).
> 사람은 다시 읽지 않는다. 코드 변환 효율과 AI 토큰 효율이 최우선.

---

## Part 1. 절대 규칙

| # | 규칙 |
|---|------|
| 1 | 줄글 금지. 모든 규칙은 표·리스트·YAML로. |
| 2 | 데이터(면·태그·효과·수치)는 YAML 코드 블록 우선. 표는 대조용. |
| 3 | "왜 이렇게 했나"는 본문 금지. 필요시 `DOCS/DESIGN/LOG/`로 분리. |
| 4 | 미확정 = `TODO(이유): trigger` 마커. 자연어 자유 서술 금지. |
| 5 | 한 규칙은 한 문서에만. 다른 곳은 `@{ID}` 참조만. |
| 6 | 변경 이력 본문 금지. git history가 보관. |
| 7 | 동의어 혼용 금지. 용어집(@FRAME-001)에 정의된 단일 표기 사용. |
| 8 | 빈 스텁 금지. 미정이면 TODO 마커만. |
| 9 | 추측 금지. 모르면 TODO. |
| 10 | 콘텐츠(카드 내용·서사·적 데이터·수치) 임의 생성 금지. 철이 작성. |

## Part 2. 메카닉 페이지 템플릿

```markdown
# {ID}: {이름}

> 상태: {미정|설계중|확정|폐기} · 의존: @{ID1}, @{ID2}

## 정의
[1~2문장. 무엇이고 왜 존재하는가. 디테일·수치 금지]

## 규칙
[결정 사항. YAML / 표 / 리스트. 줄글 금지]

## 시각 (선택)
[mermaid 또는 ASCII. 구조 파악에 필수일 때만]

## TODO (선택)
- TODO(이유): trigger
```

폐기 섹션 (v3.0 → v4.0):
- ④ 설계 근거 → LOG로 분리
- ⑤ 미확정 사항 → TODO 마커로 인라인
- ⑥ 변경 이력 → git history
- 한 줄 요약 → 정의로 흡수

### 섹션별 규칙

#### `## 정의`
- 1~2문장
- "이 메카닉이 무엇이고 왜 존재하는가"
- 디테일·수치·분기는 `## 규칙`으로

#### `## 규칙`

| 데이터 형태 | 표현 |
|-------------|------|
| 단일 규칙 | 평문 1문장 또는 표 |
| 데이터 집합 (면·태그·효과·추종자 등) | **YAML 블록** |
| 분기 조건 | 표 (조건 / 결과) |
| 순서 (스텝·페이즈) | 번호 리스트 또는 mermaid |

YAML 우선. 표는 사람 가독성보다 AI 파싱 가독성을 우선.

```yaml
# 좋은 예
unit:
  id: PLY-NL-INFANTRY
  class: 보병
  grade: nameless
  faces: { atk: 2, def: 3, star: 0, null: 5 }
  atk_power: 1
  def_power: 1
  passive: TODO(엔진): 7스텝 정합성 검토 후
```

#### `## TODO`

```
TODO(이유): trigger
```

| 필드 | 의미 |
|------|------|
| 이유 | 한 단어~짧은 구. 카테고리. 예: 밸런스/엔진/서사/UI/콘텐츠 |
| trigger | 무엇이 갖춰지면 결정 가능한가 |

예시:

| 마커 | 의미 |
|------|------|
| `TODO(서사): 1권 서사 설계 후` | 서사 카테고리. 1권 서사가 잡혀야 결정 가능 |
| `TODO(엔진): 동결 해제 후 (~2026-07)` | 엔진 카테고리. 동결 해제 시점 트리거 |
| `TODO(밸런스): 프로토타입 후` | 밸런스. 프로토 결과 의존 |

## Part 3. 헤더 규칙

```
> 상태: {state} · 의존: @{ID1}, @{ID2}
```

### 상태 4종

| 값 | 의미 |
|----|------|
| 미정 | 존재만 정의. 규칙 없음 |
| 설계중 | 규칙 작성 중. 일부 TODO 존재 |
| 확정 | 규칙 완성. 코드화 가능 |
| 폐기 | DOCS/ARCHIVE/로 이동 대상 |

폐기 항목 (v3.0 헤더 → v4.0):
- 버전 번호 → git tag로 (필요시)
- 수정일 → git log
- ID → 헤더 1줄로 통합

## Part 4. ID 체계

| 영역 | 접두사 | 예시 |
|------|--------|------|
| 코어 | CORE | CORE-001 |
| 골격 (불변/가변) | FRAME | FRAME-001 |
| 전투 — 구조 | COMBAT-STRUCT | COMBAT-STRUCT-001 |
| 전투 — 다이스 | COMBAT-DICE | COMBAT-DICE-001 |
| 전투 — 유닛 | COMBAT-UNIT | COMBAT-UNIT-NAMELESS |
| 전투 — 행동 | COMBAT-ACT | COMBAT-ACT-001 |
| 전투 — 판정 | COMBAT-JUDGE | COMBAT-JUDGE-001 |
| 스테이지 | STAGE | STAGE-CARD-001 |
| 메타 | META | META-LOBBY-001 |
| 스키마 | SCHEMA | SCHEMA-FIGURE |
| 태그 | TAG | TAG-RULE-001 |

참조 문법: 본문 어디서든 `@{ID}`로 호출. 예: `@COMBAT-STRUCT-001`.

## Part 6. 세션 유형

| 유형 | 도구 | 권한 | 산출 |
|------|------|------|------|
| 기획 | claude.ai | 읽기 | 결정 정리. 커밋 X |
