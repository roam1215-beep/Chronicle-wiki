# 판정 — 주사위 예산과 베팅

> **변동성 카드를 고르면 무엇이 어떻게 굴러가는가.** 왜 굴리나(선택의 무게·베팅) = `design/core_loop.md`. 카드 데이터·스키마 = `specs/cards.md`. 이 문서 = 굴림과 자원의 규칙.
> ※ 확정 = 본문 / 미정·프로토에서 조일 것 = "## 미정" · "## 프로토 검증 노트".

## 능력치 — 넷은 주사위, 하나는 자원

```yaml
굴리는 능력치 (= 굴릴 수 있는 주사위. 단 '유한 예산' — 아래 §주사위 예산):
  힘   — 검 성공 / 정면·무력의 행동
  민첩 — 활 성공 / 빠름·빈틈의 행동
  지혜 — 책 성공 / 읽음·꾀의 행동
  행운 — 행운 성공 / 와일드 (아래 §행운). 그 힘은 화로·그림자 두 여신의 가호에서 온다.
         ※ 옛 명칭 '가호' 폐기 — 능력치/주사위 이름은 '행운'으로 통일. (세계관의 '여신의 가호'는 별개 개념, 2_faith)

관리자원 (굴리지 않음):
  건강 — HP. 0이 되면 즉시 사망, 그 판 종료. 0.5 단위까지 쓴다. 깎이는 것이지 키워 강해지는 스탯 아님.

성격: 능력치는 '편(인격)의 색깔' + 런 내 성장. 죽으면 리셋(다음 런은 시작값부터) — 운명담, 영웅담 아님.
  영구(회차 넘는) 누적은 '수집(도감)'이 맡는다 (core_loop §수집). 능력치는 회차를 넘겨 누적하지 않는다.
```

## 주사위 — 6면, 면이 곧 결과의 종류

```yaml
힘   [검 검 검 검 · 불운 불운]
민첩 [활 활 활 활 · 불운 불운]
지혜 [책 책 책 책 · 불운 불운]
행운 [행운 행운 행운 · 불운 불운 불운]

면 = 성공 종류 : 검(힘)·활(민첩)·책(지혜)·행운(행운) / 불운 = 실패면.
  ※ 힘·민첩·지혜는 능력치명≠면명(검·활·책)이나, 행운은 능력치명=면명(행운). 행운 면은 와일드.
# 면 구성(4:2, 3:3)은 잠정 — 프로토에서 조정 (## 미정).
```

## 주사위 예산 — 유한하게 쓰고, 채우고, 마른다

```yaml
# 핵심: 능력치 수만큼 '매번' 굴리는 게 아니다. 능력치는 Episode 단위 유한 예산이다.
Episode 시작: 각 능력치 최대치만큼 주사위가 채워진다 (힘N·민첩N·지혜N·행운N).
굴림마다 소모: 건 주사위는 성패와 무관하게 예산에서 빠진다 (날린 주사위는 돌아오지 않는다).
보충: 확정형 카드의 보급품·일부 인물이 주사위를 채운다 (소모성).
Episode 클리어: 주사위 예산 풀 충전 + 능력치 상승(런 내, 죽으면 리셋). 단 요구치도 함께 오른다.
  → '들고 갈 판돈'이 커진다. 난이도 곡선(요구↑)과 성장 곡선(예산↑)이 맞물려 돈다.

건강은 예외: 회복 트리거(특정 보급품·인물·변동형 성공)로만 차고, Episode를 넘겨도 자동으로 차지 않는다.
  → 주사위는 순환 자원(단기 관리), 건강은 마르는 자원(장기 긴장 — Book 전체를 관통). 물처럼 쓰다 아차.
```

## 카드 두 종류 — 변동형은 폭을 넓히고, 확정형은 유틸을 챙긴다

```yaml
변동형: 주사위를 걸고 굴린다. '요구면' 있음 (도박).
  충족 → 상 + 인물·장비 획득 기회 + 건강 회복 (영구 빌드업 = '폭 넓히기', 큰 보상이라 위험이 줌).
  미달 → 벌 (천장 = 건강 -1 / 그 아래 = 기회·주사위만 소모 / 동료 상실도 가능).
확정형: 주사위 안 씀, 벌 절대 없음.
  → 보급품 획득 (소모성 — 주사위 보충·건강 회복 = '유틸 챙기기').
  천장이 낮다 = 인물·장비 같은 큰 보상은 못 얻는다 (안전의 대가 = 성장 기회를 놓침).

# 정체성: 변동형=위험 무릅써 미래를 키움 / 확정형=위험 피하고 현재를 버팀.
#   확정형이 영구 자원을 안 줘 'ATM'이 안 되고, 변동형이 영구 빌드업을 줘 '걸 가치'가 생긴다.
#   (프로토 v1 무른점 — 확정형 무의미·내놓고 못 얻음 — 이 구조로 풀림. ## 프로토 검증 노트.)
```

## 베팅 — 몇 개 걸지 플레이어가 정한다

```yaml
변동형/운명 카드를 고르면, 요구 능력치 주사위를 예산에서 '몇 개 걸지' 직접 정한다.
  색만 보인다(정확 요구 수는 가림 — §표시). "장정 셋"이면 두엇 / "장정 여덟"이면 여럿 — 상황 묘사로 무게를 가늠해 건다.
  → "지금 질러 확실히? 아껴서 운에 맡겨?" 가 매 선택의 핵심. 정확 수치가 아니라 감으로 마진을 잰다.
함께 걸 수 있는 것:
  + 행운 주사위 (와일드 보조 — §행운).
  + 장비가 준 임시 주사위 (무기·도구 — §빌드).
  + 인물 카드락 (결과면을 굴림 없이 확정해 메움 — §빌드).
판정 (2단계 — 부분 성공 없음):
  나온 성공(요구 면 + 행운 와일드 + 카드락 확정) ≥ 요구 수 → 충족(상) / 미만 → 미달(벌).

시나리오로: 결과는 숫자가 아니라 '일어난 일'로 서술 (작가가 카드마다 상/벌 텍스트를 미리 박는다).
  충족 "도적을 물리쳤다" / 미달 "물리쳤지만 부상을 입었다" (= 건강 -1).
  → 미달은 '실패=죽음'이 아니라 '해냈으나 대가를 치름'. 운명은 한 방에 죽이지 않고 기울인다.
```

## 행운 — 두 여신의 와일드카드

```yaml
행운 주사위의 '행운' 면은 원하는 성공 면으로 바꿔 적용한다 (부족분을 메운다).
  예: 요구 "검 2", 굴림 [검][행운] → 행운을 검으로 → 검 2 충족.
  → 어떤 요구든 메워주는 만능 조커. 단 행운 주사위는 면 절반이 불운이라 잘 안 뜬다 (희소).

서사 정합: 그 힘은 화로·그림자 두 여신의 가호. 검도 활도 책도 아닌, 부족분을 채우는 초월적 손길.
  행운이 떠서 운명을 넘기는 순간 = 여신이 개입한 순간. 메커니즘이 곧 기적. (2_faith — 회귀를 일으키는 힘의 판 내 현현.)
```

## 용어 — 소모·소진·파손

```yaml
소모: 주사위를 건다(쓴다). 건 주사위는 성패 무관 예산에서 빠진다 (§주사위 예산).
소진: 소모품(보급품)을 쓴다 → 사라진다.
파손: 장비가 닳는다 (내구도 — §빌드). 무기·도구는 '실패' 흡수로, 방어구는 '피격' 흡수로 파손.
```

## 빌드 — 인물·장비·보급품 (상세 = cards.md)

```yaml
# 주사위·예산·면에 개입하는 세 종류. 카드 스키마·등급·슬롯·예시 = specs/cards.md.
인물:   스탯·특수효과를 맡는다. 영구 스탯(높은 등급) / 카드락(결과면 확정)·재굴림 등.
        변동형 성공으로 얻고, 벌로 잃을 수 있다 (건강과 별개 자원).
장비 (3슬롯, 무기/도구/방어구):
  무기 = 임시 주사위 부여 (힘·민첩).  도구 = 임시 주사위 부여 (지혜·행운).
         걸어서 '실패'하면 내구도 -1, 0이면 '파손'. 내구도 = 등급(일반1·희귀2·영웅3·전설∞). 성공 '소모'는 재사용.
  방어구 = 임시 건강 방패. 피격 시 먼저 흡수되고 '파손'.
보급품 (3슬롯, 소모성): 확정형이 줌. 주사위 보충·건강 회복. 쓰면 '소진'.
# 옛 '면 고정·탄약(활-화살)·장신구' 폐기 — 결과면 확정은 인물 카드락이 맡는다.
```

## 운명전 — 쌍을 골라, 가린 내역을 탐색해 채운다

```yaml
운명전은 두 격:
  Episode 운명 (1·2·4·5·7·8): 3갈래(A 힘/민첩 · B 민첩/지혜 · C 힘/지혜) 중 택1, 고른 갈래의 2능력치를 채운다.
  챕터 운명 (3·6·9): 갈래 택1 없이 힘·민첩·지혜를 모두 채운다 — 챕터를 닫는 더 무거운 시험(피할 약점이 없다).

표시 (가림은 '내역'에만):
  능력치 쌍(episode)/셋(chapter) + 도합 N 공개 / 내역(각 몇 개)은 가림.
  → 쌍을 보고 내 패에 맞는 길을 고르되, 내역은 모른 채 들어선다 = "운명은 가늠할 수 없다".
    앞서 고른 ordeal 충족이 그 능력치 내역을 깐다 (가림 → 보임 = 포석).

채우기 (순차가 '갈래 안'으로 내려옴 — 탐색):
  요구치를 모른 채 주사위를 나눠 던진다 (예산 다하기 전까지 여러 번). 요구 면이 뜨면 자동 충족.
  카드락(인물): 한 면 확정 시도 — 그 능력치 요구 남았으면 즉시 채움 / 없으면 '소모'만 + 정보("그 능력치 끝").
  건 주사위는 성패 무관 소모 — 모르고 과하게 걸면 낭비. 포석·카드락이 낭비를 줄이는 정보 도박.

판돈: 앞서 고른 ordeal이 운명을 빚는다 — 충족하면 그 능력치 require ↓ + 내역 공개(포석), 미달하면 ↑ (cards §fate_pull).
  인물·장비가 패를 키우고, 건강이 깎였으면 위태롭다. (안 고른 카드·일반 선택은 영향 없음)

종료:
  생존 → 고른 갈래(episode)/전체(chapter)의 능력치를 다 채움. 운명-죽음이 운명-생존으로 flip (core_loop).
  사망 (둘) → 주사위 예산 소진 + 요구 미충족 / 건강 0. → 회귀.
```

## 표시 — 수치를 숨기고 가늠을 준다

```yaml
주사위 눈 확률(검4 불운2 등)은 화면에 노출하지 않는다 — 계산 불가 → 베팅을 '도박꾼의 감'으로 (BG3 체력 바 결).
  굴림은 구르는 모션으로 보여주되(긴장), 확률·눈 구성은 숨긴다. (= 텍스트가 죽지 않는 이유 — core_loop)
예외: '쓰는/세는 자원'은 정확히 보여도 된다 — 주사위 예산(남은 개수)·행운·슬롯·건강(0.5 단위).
  → 관리가 필요한 자원은 정확히, 운에 맡기는 굴림은 흐릿하게. 둘을 섞는다.

카드 요구 수치도 노출하지 않는다 — '결과면 N이니 주사위 M개' 기계적 즉답을 막는다(= 텍스트가 유일한 힌트).
  결정 카드: 색(요구 능력치 경향)은 보이되 정확 요구 수는 가림 — "뭘로 풀지"는 즉시, "얼마나"는 상황으로 유추 (가벼운 층).
  운명전: 색·내역 다 가림 — 쌍/셋·도합만 공개, 각 요구는 ordeal로 벗김 (무거운 층·클라이맥스).
  → 가림 강도가 결정 < 운명으로 차오른다. 결정 Phase가 가벼워야 운명전의 조임이 산다.
  초반 Episode는 요구 1로 뻔하고(학습 구간), 후반으로 갈수록 유추가 필요해진다(회귀로 배워가는 곡선).
```
