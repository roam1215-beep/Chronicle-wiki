# 판정 — 주사위와 능력치

> **변동성 카드를 고르면 무엇이 어떻게 굴러가는가.** 왜 굴리나(선택의 무게·베팅) = `design/core_loop.md`. 이 문서 = 그 굴림의 규칙.
> 이 문서는 옛 `combat.md`(체스+하스스톤 유닛 전투)를 대체한다 — combat·types의 격돌/타입 6종은 이 코어에서 내려간다(폐기 대기).
> ※ 확정 = 본문 / 미정·프로토에서 조일 것 = "## 미정" · "## 프로토 검증 노트".

## 능력치 — 넷은 주사위, 하나는 자원

```yaml
굴리는 능력치 (각 능력치 수 = 그 주사위를 굴리는 개수):
  힘   — 검 성공 / 정면·무력의 행동
  민첩 — 활 성공 / 빠름·빈틈의 행동
  지혜 — 책 성공 / 읽음·꾀의 행동
  가호 — 행운 성공 / 화로와 그림자 두 여신이 준 힘 (와일드 — 아래 §가호)

관리자원 (굴리지 않음):
  건강 — HP. 0이 되면 즉시 사망, 그 판 종료. 깎이는 것이지 키워서 강해지는 스탯 아님.

성격: 능력치는 '편(인격)의 색깔'이지 성장이 아니다. 런마다 리셋, 회차 누적 없음 (운명담 — 영웅담 아님).
  영구 누적은 '운명-생존 수집'이 맡는다 (core_loop). 능력치까지 누적시키지 않는다.
```

## 주사위 — 6면, 면이 곧 결과의 종류

```yaml
힘   [검 검 검 검 · 불운 불운]
민첩 [활 활 활 활 · 불운 불운]
지혜 [책 책 책 책 · 불운 불운]
가호 [행운 행운 행운 · 불운 불운 불운]

면 = 성공 종류 : 검(힘)·활(민첩)·책(지혜)·행운(가호) / 불운 = 실패면.
# 면 구성(4:2, 3:3)은 잠정 — 프로토에서 조정 (## 미정).
```

## 카드 두 종류 — 확정형과 변동형

```yaml
확정형: 주사위를 굴리지 않는다. 결과가 정해져 있다 (위험 없음·확실함).
변동형: 주사위를 굴린다. '요구면'이 있다 (도박 — 충족하면 상, 모자라면 벌).

# 확정형은 '도박을 피하는 안전한 길'이자, 변동형이 못 주는 것(예: 확실한 동료 확보 = 토대)을 준다.
#   변동형의 위험이 충분히 무거울 때만 확정형이 유혹이 된다 (## 프로토 검증 노트 — 현재 약함).
```

## 요구면과 판정 — 충족이면 상, 미달이면 벌 (2단계)

```yaml
변동성 카드에는 요구면이 있다 (예: "검 2" = 검 성공 2개 필요).
  1. 요구된 능력치의 주사위를, 능력치 수만큼 굴린다 (힘 2 → 힘 주사위 2개).
     + 가호 주사위도 함께 굴린다 (가호 수만큼) — 행운 면은 와일드(§가호).
  2. 나온 성공(요구 면 + 가호 행운) 합이 요구 수 이상이면 → 충족, 미만이면 → 미달.
  3. 결과 (2단계 — 부분 성공 없음):
       충족 → 상 (피해 없이 넘어감, 또는 이득)
       미달 → 벌 (건강 깎임 등)

시나리오로: 결과는 숫자가 아니라 '일어난 일'로 서술된다 (작가가 카드마다 상/벌 텍스트를 미리 박는다).
  충족 "도적을 물리쳤다" / 미달 "물리쳤지만 부상을 입었다" (= 건강 -1)
  → 미달은 '실패=죽음'이 아니라 '해냈으나 대가를 치름'. 운명은 한 방에 죽이지 않고 기울인다.

# 벌의 크기(건강 몇), 상의 크기는 카드마다 — 무모할수록 진폭이 커야 베팅이 짜릿 (## 프로토 검증 노트).
```

## 가호 — 두 여신의 와일드카드

```yaml
가호 주사위의 '행운' 면은 원하는 성공 면으로 바꿔 적용한다 (부족분을 메운다).
  예: 요구 "검 2", 굴림 [검][행운] → 행운을 검으로 → 검 2 충족.
  → 어떤 요구든 메워주는 만능 조커. 단 가호 주사위는 면 절반이 불운이라 잘 안 뜬다 (희소).

서사 정합: 화로·그림자 두 여신이 준 힘. 검도 활도 책도 아닌, 부족분을 채우는 초월적 손길.
  가호가 떠서 운명을 넘기는 순간 = 여신이 개입한 순간. 메커니즘이 곧 기적.
  (회귀를 일으키는 그 힘의 판 내 현현 — 2_faith.)
```

## 동료와 장비 — 다른 방식으로 굴림을 돕는다

```yaml
동료 (영입): 굴리는 주사위 '수'를 늘린다. (곁에 키레네아 → 그 굴림에 주사위 +1)
장비:        주사위 '면'을 바꾼다. (좋은 칼 → 힘 주사위의 불운 면 하나가 검으로)
  → 둘이 안 겹친다. 동료=양(수), 장비=질(면). 빌드가 두 축으로 깊어진다.

획득: 페이즈의 선택(주로 확정형·충족한 변동형)이 동료·장비를 남긴다.
  이 흔적이 운명전의 판을 짠다 (앞선 선택이 클라이맥스에서 회수됨 — core_loop).
```

## 운명전 — 요구면을 가린 베팅

```yaml
운명전도 일반 페이즈와 같은 구조 = 카드 3장 중 1택, 골라서 굴림.
  결정적 차이: 운명 카드는 요구면을 '가린다' (어느 능력치로 굴리는지 아이콘은 보이되, 요구 수는 안 보임).
  3장 = 이 운명을 무엇으로 감당할지 (힘 / 민첩 / 지혜로 거는 3갈래).
  → 플레이어는 요구를 모른 채, 내 패(능력치·동료·장비·가호·건강)를 믿고 베팅한다.
  → "운명은 가늠할 수 없다" — 일반 사건은 요구가 보이나, 운명 앞에선 보이지 않는다 (주제의 구현).

앞 페이즈에서 쌓은 모든 것이 여기서 판돈:
  적을 솎았으면(thinned) 운명 요구면이 낮아지고, 동료가 있으면 주사위가 늘고, 퇴로가 있으면 미달해도 살길이 있고, 건강이 깎였으면 위태롭다.

결과:
  충족 → 생존. 운명-죽음 카드가 운명-생존으로 뒤집힌다 (정해진 죽음을 다시 씀 — core_loop).
  미달 → 죽음 → 회귀. (단 퇴로 등 조건이 있으면 '간신히' 생존하는 갈래도 — 작가 재량)
```

## 표시 — 수치를 숨기고 가늠을 준다

```yaml
모든 능력치·자원은 정확한 숫자가 아니라 게이지로 '어렴풋이' 보인다 (BG3 적 체력 바 결).
  주사위 구성(검4 불운2 등)은 내부적으로 정확하나, 화면엔 확률·수치를 노출하지 않는다.
  → 계산을 불가능하게 만들어, 베팅을 '도박꾼의 감'으로. (= 텍스트가 죽지 않는 이유 — core_loop)
  굴림은 구르는 모션·소리로 보여주되(긴장), 확률·눈은 숨긴다.
예외: 가호·동료 수처럼 '쓰는/세는 자원'은 정확히 보여도 된다 (관리가 필요하므로).
```

## 시작값 + 미정

```yaml
전사 테오도라 시작 (잠정): 힘 2 / 민첩 1 / 지혜 1 / 가호 1 / 건강 ?
  편마다 색이 다름 (사냥꾼=지혜·민첩↑, 사제=가호↑ 등 — 미정).

# 미정 (종이로 확정 불가 — 프로토/플레이테스트가 정함):
#   - 능력치 최대치, 시작 분배, 건강 수치
#   - 주사위 면 비율 (4:2 / 3:3)
#   - 요구면 크기 (검 2가 적정한가), 운명전 요구가 얼마나 높은가
#   - 벌의 크기(건강 감소량), 상/벌 진폭
#   - 가호 면 비율, 동료의 주사위 +량, 장비의 면 개선폭
```

## 프로토 검증 노트 (2026-06-28 1차 플레이)

```yaml
# 첫 플레이어블(chronicle_stage1_proto)에서 드러난 '무른' 지점 — 다음 조정 대상.
1. 확정형이 무의미: 변동형 위험이 약해 안전을 택할 이유가 없음.
   → 건강을 줄여 미달(-1)을 아프게 / 확정형에 고유 가치(동료=운명전 결정타)를 부여.
2. 스탯 편식: 제일 높은 능력치 카드만 고르면 됨 → '정답 찾기'로 회귀.
   → 한 페이즈의 세 카드를 서로 다른 능력치로 가르기. 한 스탯 올인이 가린 운명전에서 독이 되게.
3. 상/벌 진폭 약함: 둘 다 밋밋. → 무모한 카드일수록 상은 더 탐나게, 벌은 더 아프게(비대칭).
4. 스토리 미정련: 상/벌 텍스트 = 철님 창작 영역. 구조(1~3) 단단해진 뒤 입힌다.
# 핵심: 위는 전부 수치·구조 조정이지 새 시스템이 아니다. 만지며 조인다.
```
