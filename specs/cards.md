## 카드 형태 (공통)

```yaml
모든 카드: 최 상단 좌측 이름 / 최 상단 우측 카드 종류와 등급 / 중앙 상단부터 가운데 일러스트 / 중앙 하단 설명·효과.
필드: { name, kind, art, desc, effect(효과), grade }
```

## 카드 종류

```yaml
상황 카드 (Situation — 현재 장면/상황을 제시하는 서사적 프레임):
  지금 무슨 일이 벌어지고 있는가. 상세 = "## 상황 카드 — 의미와 역할".

결정 카드 (Decision — Phase에서 고르는 행동):
  현재 Situation에서 플레이어가 무엇을 하려고 하는가. 상세 = "## 결정 카드 — 의미와 원칙".

전승/획득 카드 (얻어서 빌드에 쌓임):
  인물(character) — 스탯·특수효과(카드락·재굴림 등).
  장비(equipment) — 무기·도구·방어구. 임시 주사위(무기=힘·민첩 / 도구=지혜·행운)·건강 방패(방어구) 부여. 3슬롯.
  보급품(supply)  — 소모성 유틸(주사위 보충·건강 회복). 3슬롯.
  # TODO (별도 Unit): 이 세 계열의 획득·상실 경로 미정.

운명 카드 (Fate): Episode 그릇 1장 (Phase 4 운명전). 3갈래(episode)/전체(chapter) 택1 판정. 충족 → 죽음 카드가 생존 flip / 미달·주사위 소진 → 사망·회귀 (core_loop §수집).
운명·죽음 카드 (Death): 프롤로그(매 Episode 도입)에 그 장면의 죽음을 보여줌 — 선택 X, 그릇 밖. default 원형 1장(미리 씀) + 회귀 후 상태 기반 렌더 (structure §죽음 모델). 판정 경로로 '어떻게 죽었나' 표시, 운명전 생존 시 생존 flip → 도감 (수집).
에필로그 카드 (Narrative): 그 장면 끝(운명전 클리어 후) 닫는 서술 — 굴림·수집 X, 그릇 밖.
```

## 상황 카드 — 의미와 역할

```yaml
정의:
  Situation은 현재 장면·상황을 제시하는 서사적 프레임이다.
  Situation이 답하는 것 — 지금 무슨 일이 벌어지고 있는가.
  Decision이 답하는 것 — 그 상황에서 무엇을 할 것인가.
  플레이어가 수행할 행동 자체는 Decision에서 선택한다.

서사 역할 분담:
  Situation이 장면의 주요 서사적 맥락을 담당한다.
  Decision은 그 Situation 안에서 가능한 행동을 상대적으로 간결하게 제시한다.
  공통 장면 맥락은 Situation이 주로 담당하며,
    동일한 공통 배경 설명을 세 Decision마다 반복하는 것을 기본 구조로 삼지 않는다.
    → Decision에 그 행동을 이해하는 데 필요한 국소 맥락이 들어가는 것은 막지 않는다.
  # Decision의 텍스트 길이·줄 수 등 콘텐츠 규격은 여기서 정하지 않는다.

제한 시점:
  Situation은 전지적 세계 설명서가 아니다.
  그 이야기·인물의 제한된 시점에서, 지금 그 인물이 접하고 있는 상황을 제시한다.
  객관적 세계 전체의 진실을 Situation 한 장이 직접 설명하는 구조로 만들지 않는다.

판정·효과와의 관계:
  Situation의 본질적 기능은 상황 제시다.
  Situation 자체에 판정이나 기계 효과가 붙는 것은 필수 구성요소가 아니다.
  현재 기본 판정의 주체는 Decision이다.
  # TODO: Situation 자체 효과 시스템은 미정. "효과를 가질 수 없다"로 확대 해석하지 않는다.
  # TODO: Situation schema·Phase/위계와의 대응은 후속 Unit (structure §서사 단위).
```

## 결정 카드 — 의미와 원칙

> 무엇을 언제 공개하는가(런타임 정보 공개 순서) = `specs/dice.md` §정보 공개.

```yaml
정의:
  Decision 카드는 현재 Situation에서 플레이어가 무엇을 하려고 하는가를 나타내는 행동 선택이다.
  역량 종류·색깔·난이도를 직접 고르는 버튼이 아니다.

집필 방향:
  먼저 행동·서사가 존재하고, 판정 요구는 그 행동으로부터 파생한다.
  힘 카드·민첩 카드를 먼저 정한 뒤 그 역량에 맞는 서사를 붙이는 방식은 쓰지 않는다.
```

### 성공과 실패

```yaml
성공 = 선택한 행동을 의도한 대로 달성함.
실패 = 선택한 행동을 의도한 대로 달성하지 못함.

성공은 좋은 결과·보상과 동의어가 아니다.
실패는 나쁜 결과·처벌과 동의어가 아니다.

성공과 실패는 각각 결과 서사를 반드시 가진다.
optional인 것은 기계 효과뿐이다. 네 경우를 모두 허용한다.
  성공 + 효과 있음 / 성공 + 효과 없음 / 실패 + 효과 있음 / 실패 + 효과 없음

효과는 성공·실패라는 라벨 때문에 기계적으로 붙는 것이 아니라,
그 결과에서 실제로 무슨 일이 일어났는가라는 서사적 인과에서 파생한다.
  행동에는 성공했지만 자연스럽게 고갈 등의 비용이 발생할 수 있다.
  행동에는 실패했지만 별도의 기계 효과가 없을 수도 있다.
```

### 다시 하기 유인

```yaml
모든 성공에 공통 보상을 붙이지 않는다.
모든 실패에 공통 페널티를 붙이지 않는다.
플레이어가 반드시 다시 하기를 고르도록 만드는 보편적 압박 시스템을 두지 않는다.

실패를 확정하고 미래의 주사위 상태를 보존하는 것은 허용되는 정상적인 플레이다.
# 현재는 이에 대해 별도 규칙을 추가하지 않고 플레이테스트한다.
```

### 요구 기호 작성 원칙

```yaml
요구는 "이 행동을 제대로 해내기 위해 실제로 필요한 것이 무엇인가"에서 파생한다.
요구 = Decision 서사의 물리적·인지적·상황적 부담을 기계적으로 번역한 것.

요구 추론을 문장 속 특정 단어나 역량명에 대응시키는 키워드 퀴즈로 만들지 않는다.
요구가 공개됐을 때 플레이어가 서사를 다시 보며 왜 이런 요구가 나왔는지 납득할 수 있어야 한다.
정확한 기호 수치까지 사전에 예측 가능할 필요는 없으나, 서사와 요구의 인과가 크게 어긋나선 안 된다.
테스트 플레이어 다수가 같은 서사를 읽고 제작 의도와 전혀 다른 종류의 요구를 예상한다면,
  플레이어가 아니라 카드 서술을 먼저 의심한다.

행운은 난이도 조절이나 밸런스용 filler로 넣지 않는다.
```

## 장비 (equipment) — 무기/도구/방어구

```yaml
무기(weapon):   임시 주사위 부여 (힘·민첩 계열). 걸어서 '소모'한다.
도구(tool):     임시 주사위 부여 (지혜·행운 계열). 무기와 같은 규칙.
방어구(armor):  임시 건강 방패 부여. 피격 시 먼저 흡수되고 '파손'.

내구도 (= 등급, 무기·도구):
  부여한 임시 주사위를 걸어 '실패'하면 내구도 -1. 0이면 '파손'(제거).
  일반 1 / 희귀 2 / 영웅 3 / 전설 ∞ (실패 흡수 횟수).
  → 성공으로 '소모'되면 안 닳고 다음 Episode 재사용. 실패만 닳는다 (장비에 숙련이 쌓이는 결).
# 옛 '면 고정(보급품/탄약 태우기)·장신구' 폐기. 결과면 확정의 알맹이는 인물(카드락)으로 옮김.

예시 (잠정 — 작가 정의):
  낡은 한손검        / 무기 / 일반 / 임시 힘 주사위 +1   / 실패 시 파손
  투박한 활          / 무기 / 일반 / 임시 민첩 주사위 +1 / 실패 시 파손
  낡은 지도          / 도구 / 일반 / 임시 지혜 주사위 +1 / 실패 시 파손
  투박한 나무 조각상 / 도구 / 일반 / 임시 행운 주사위 +1 / 실패 시 파손
  천 갑옷            / 방어구 / 일반 / 임시 건강 +0.5 / 피격 흡수 후 파손
  가죽 갑옷          / 방어구 / 희귀 / 임시 건강 +1   / 피격 흡수 후 파손
```
