# 운영규칙 v6.0

> Chronicle 위키 운영. 두 Claude 공용.
> 본문 = 명세·데이터·설계 의도. 변경 이력 X.

## 1. 절대 규칙

| # | 규칙 |
|---|------|
| 1 | 본문 = 명세만 (specs) / 데이터만 (content) / 설계 의도만 (design) |
| 2 | YAML/표/의사코드 우선. 산문 자제. |
| 3 | 한 개념 = 한 정본 (SSOT). 중복 X. 다른 곳은 링크. |
| 4 | 미확정 = `TODO(이유): trigger` 마커. 자연어 자유 서술 X. |
| 5 | 콘텐츠(카드 텍스트·서사·수치) 임의 생성 X. 철님 결정으로만. |
| 6 | 추측 X. 모르면 TODO. |
| 7 | 변경 이력·폐기 표·본인 결정 인용 X. (git log가 보존) |

## 2. 폴더 구성

```yaml
specs/        결정론적 (스키마·알고리즘·수치)
content/      데이터 (실제 카드·인물·콘텐츠)
design/       작품·서사·UI (claude.ai 전용)
00_운영/      운영
```

## 3. 페이지 구조

### specs/ 페이지

```markdown
# {이름}

## {구조 단위}

```yaml
{스키마 / 알고리즘 / 수치}
```

## TODO
- TODO(이유): trigger
```

### content/ 페이지

```markdown
# {Order/인물/스테이지}

```yaml
{데이터 — specs/ 스키마 따름}
```

## TODO
- TODO(이유): trigger
```

### design/ 페이지

```markdown
# {주제}

## {묶음}

{시적 표현·맥락 OK. 단 specs/ 와 충돌 X}

## TODO
- TODO(이유): trigger
```

## 4. 세션 유형

| 유형 | 권한 | 산출 |
|------|------|------|
| 작업 | 읽기/쓰기 | 결정 + 변경 + 커밋 (디폴트) |
| 읽기 | 읽기 | 진단/탐색만. 커밋 X |

## 5. 세션 흐름

```bash
1. STATE.md 부팅 (단일 진입점)
2. 폴더 라우터로 작업 영역 진입
3. 작업 진행
4. spot check:
   - grep으로 옛 어휘 잔재 검증
   - 변경 파일 본문 점검 (부풀음 의심)
5. 일괄 승인 → 커밋 → push
6. STATE.md 갱신
7. 로컬 레포 삭제 (토큰 흔적 제거)
```

## 6. 자동 트리거 (본문 작성할 때마다)

```yaml
1. 결정론적인가?
   YES → specs/
   NO  → design/ 또는 content/

2. 다른 파일에 있나? (SSOT)
   YES → 정본 1개, 나머지 링크
   NO  → 그대로

3. 결정 이유·맥락이 specs/에 있나?
   YES → design/ 이동

4. 부풀음 검증:
   specs/ 파일 100~200줄 유지
   design/ 더 깊어도 OK
   본문 부풀음 자체가 검증 트리거
```

## 7. 커밋

| 항목 | 값 |
|------|-----|
| 형식 | `[카테고리] 내용` |
| 단위 | 1 작업단위 = 1 커밋 |
| 승인 | 한 세션 내 일괄 승인 |
| 분할 | default X (자연스러운 단위로만) |

## 8. 메모리 vs git

```yaml
git이 진리. 메모리 ≪ git.
충돌 시 git 따름.
추측 X (모르면 git 보고 답).
```

## 9. 폐기 정책

```yaml
방식: git rm (히스토리는 git log 보존)
ARCHIVE 폴더 X (5-5 폐기)
근거 보존: 큰 폐기는 커밋 메시지에 사유
```
